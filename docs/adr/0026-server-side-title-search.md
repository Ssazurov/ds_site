# ADR-0026: Серверный поиск по названию через GAR

**Статус**: Принято  
**Дата**: 2026-10-01  
**Контекст**: ds_site#131, зависит от gar-core-api#444

## Контекст

Поиск по названию документов (`?q=`) работал локально на клиенте (`lib/title-search.ts`): фильтрация выполнялась по уже загруженным документам, что ограничивало результаты одной порцией (20 документов) и не учитывало весь корпус.

С реализацией серверного параметра `q` в GAR `/public/documents` (gar-core-api#444) стало возможным передать поиск на сервер: GAR выполняет полнотекстовый поиск по title/doc_name и возвращает корректные facets/total для отфильтрованного набора.

## Решение

Удалён флаг `searchAll` из `lib/use-document-feed.ts`:
- Параметр `q` теперь всегда передаётся в GAR через `getDocuments(..., { q, ... })`
- Серверная фильтрация работает на всём корпусе, а не на загруженной порции
- Фасеты (domains, types) и total обновляются корректно для поискового запроса
- Локальная функция `filterByTitle` (lib/title-search.ts) сохранена для страницы `/favorites` (поиск в избранном работает локально, т.к. избранное хранится в localStorage)

## Последствия

✅ Поиск по всем документам датасета, не ограничен загруженной порцией  
✅ Корректные facets/total для поискового запроса: фильтры отражают реальное распределение в результатах поиска  
✅ Код упрощён: нет дублирования логики поиска на клиенте и сервере  
✅ Производительность: фильтрация выполняется на сервере с индексами

⚠️ Требует GAR с поддержкой параметра `q` (gar-core-api#444, релиз ≥2026-10-01)  
⚠️ Локальный поиск в `/favorites` остаётся клиентским (избранное недоступно серверу)
