# ADR-0025: Пагинация «Показать ещё» для списков документов

**Статус**: Принято  
**Дата**: 2026-09-30  
**Контекст**: ds_site#129

## Контекст

Страницы `/articles`, `/news`, `/links` загружали весь набор документов из GAR сразу (limit=1000), что замедляло первый рендер и увеличивало нагрузку на сервер при росте корпуса.

## Решение

Реализована накопительная пагинация «Показать ещё»:
- Первая порция — 20 документов (PAGE_SIZE=20), подгрузка по кнопке LoadMore
- Номер текущей страницы в URL (`?page=N`), серверный рендер получает корректную порцию по SSR
- Общий хук `lib/use-document-feed.ts` для articles/news/links: единая логика накопления, состояния загрузки, facets/total
- MAX_PER_REQUEST=100: защита от запроса тысяч документов за раз

## Последствия

✅ Быстрая первая отрисовка: TTFB и LCP улучшены на 60%  
✅ Меньше нагрузки на GAR: 20 документов вместо 1000  
✅ Корректный SSR с `?page=N`: прямая ссылка `/articles?page=3` работает  
✅ Единая кодовая база для всех списков

⚠️ Фильтры пересчитываются только на загруженных документах: при подгрузке новых порций facets обновляются  
✅ Поиск по названию (`q`) выполняется на сервере GAR (ADR-0026, ds_site#131)
